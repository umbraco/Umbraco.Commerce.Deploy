# Upgrade to Umbraco 19

From Umbraco Commerce `[18.1.0, 18.999.999)` + Umbraco Deploy `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` + Umbraco Deploy `19.0.0-beta1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `v19/topic/cms-19-upgrade` → PR into `release/19.0.0`, both cut from `main` (`a53c4ce`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` and Umbraco Deploy `19.0.0-beta1` (Deploy tag `release-19.0.0-beta1`, MyGet `umbracoprereleases`). The package's own version is `19.0.0-beta.1`.

The package has no direct `Umbraco.Cms.*` references; CMS changes reach it through Commerce (Core repo, `docs/upgrades/v19.md`) and Deploy (umbraco/Umbraco-Deploy PRs #1162 and #1163).

## Breaking changes for consumers

- Requires Umbraco 19, Umbraco Commerce 19 and Umbraco Deploy 19 (.NET 11). Deploy 19 won't transfer to or from a Deploy 18 environment.
- `UmbracoCommerceDeployComponent` constructor no longer takes `ITransferEntityService`; entity types are registered on `DeployEntityTypesOptions` in `UmbracoCommerceDeployComposer`.
- `UmbracoCommerceVariantsEditorValueConnector.VariantsBlockEditorLayoutItem` now derives from `BlockLayoutItemBase`; obsolete `ContentUdi`/`SettingsUdi` removed.

## Follow-ups

- `ShippingMethodArtifact` has an `[Obsolete("Now handled via CalculationConfig")]` member with no removal version: decide whether to remove it.
- `UmbracoCommerceDeployComponent` still writes/deletes `.uda` files through `EventHub` + `AsyncHelper.RunSync`; consider async notification handlers.
- Raise the Commerce and Deploy floors to `19.0.0` at the stable release, and recheck the `NuGet.config` mapping then: `Umbraco.Commerce.*` restores from MyGet only, and stable Commerce ships to nuget.org (applies to every add-on).
- Pre-existing, by design: on SQLite, Commerce Deploy points Commerce at its own `Umbraco.Commerce.sqlite.db`, so a site that already keeps Commerce data in `Umbraco.sqlite.db` (the DemoStore) boots with an empty store and its product pages 500. Worth a docs note or a check before switching.
- DemoStore `release/19.0.0` still has a data type on the removed `Umbraco.MediaPicker` editor; a Deploy schema import of the whole site fails on it. DemoStore issue, not this package.
- Commerce Core: variant layout items saved on v19 carry `key: 00000000-...` (from `BlockLayoutItemBase`), same as what Deploy now writes. Check with Core whether variants need a real layout key for reusable elements.

## Backport candidates

- Empty-string price handling in `UmbracoCommercePriceValueConnector`: a price saved as `{"<currency>": ""}` (no price for that currency) failed to parse, logged an error per item (135 on a DemoStore export) and dropped the whole price. Fixed in `eb0abea`: empty strings read as no price, numeric strings are parsed, anything else is a warning for that currency only. Same code on v18 and v17: backported as `v18/topic/empty-price-value` → `hotfix/18.1.1` and `v17/topic/empty-price-value` → `hotfix/17.1.1` (11-11-2026; v18 re-tested on a v18 DemoStore, v17 build only).
